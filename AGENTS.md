# Project conventions

- Keep visual refinements in existing shared components and global layout utilities; retain route-specific content and the established SSR/prerender/SEO architecture to avoid duplicated page systems.
- Keep Home and Services on the same shared Navigation; compact the existing desktop layout for laptop widths rather than adding a second header. Homepage About uses a floated portrait at wider widths so longer text can continue beneath it.
- Reveal independently positioned content with its own viewport trigger; avoid a shared trigger that can stay offscreen on phones, and use vertical motion where horizontal transforms would overflow tablet layouts.
- Keep button labels wrap-safe and mobile navigation independently scrollable so existing destinations remain usable on narrow or short screens.
- Render dropdown destination links with Radix's `asChild` so pointer and keyboard selection activate the same link; keep testimonial rotation optional and disabled under reduced motion.
- Use src/config/resourceLinks.ts for the repeated buyer-guide and market-report destinations; keep unique guides and area-filtered searches local because their targets and behavior differ.
- Use src/lib/blogDate.ts for machine-readable article publication dates while retaining the existing displayed dates; reject invalid input instead of inventing a date.
- Keep page-main script accents on shared bounded CSS scales with useHeadingFit in AppShell fitting actual text to its content area after fonts load, resize, and route/content changes; readable wrapping remains below the shared minimum size, so future headings need no page-specific sizing. Retain `.eyebrow-col` and `.h-section-sm` for paired columns, semantic Button variants, and body typography in navigation. Shared icon-heading rows align icons from the heading line height rather than screen-specific offsets.
- Never remove JSX elements with broad shell text substitutions that can also delete unrelated closing tags; make targeted, element-specific edits and confirm each edited file still parses and renders before moving on.
- Keep area-photo text panels in the shared global selector; calibrate script leading against rendered glyphs and verify every area at laptop and phone widths so font metrics do not create oversized or off-center boxes.
